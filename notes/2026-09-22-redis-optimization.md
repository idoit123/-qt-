# Redis 优化与校招表述
日期：2026-09-22

用户请求：“帮我增加redis来优化吧”。已在 Linux EpollServer 实现；Qt 基线和协议保持兼容。

## 已实现
- hiredis 可选构建，环境变量启用，连接复用、超时和 AUTH。
- 好友列表 Cache-Aside 缓存，服务于好友刷新和好友群发。
- TTL、空列表缓存、增删好友后双方失效、失败命名空间切换及重连冷却回源。
- 进程内通过互斥锁串行化回填与更新，避免缓存旧值覆盖；实例命名空间隔离重启与不同数据库。
- SQLite 双向好友索引、缓存与 SQL 读取统计。
- 真实 Redis 一致性/故障集成测试和可复现的微基准。

## 测试
Redis 开启构建通过 3/3 CTest，包括原协议测试、无缓存聊天和 Redis 集成测试。缓存测试覆盖命中、空值、双向失效、并发读写、TTL、损坏值、读取和失效超时、回源更新后恢复、实例隔离、SQL 查询失败不回填、AUTH 和真实 20 客户端/1000 条私聊。具体日志见 2026-09-22-redis-ctest.txt。

## 实测解释
原始 JSON：2026-09-22-redis-benchmark.json。
单线程 Database::friends；两组 SQLite 均有索引；3 轮，每轮先预热一次，再读取同一用户 500 次。
- 1000 用户/5 万条好友关系/返回 100 人：耗时中位数 57.44 ms -> 54.59 ms，约下降 4.97%，波动明显，不宜作为稳定吞吐提升宣传。
- 20 用户/60 条好友关系/返回 6 人：31.79 ms -> 53.66 ms，缓存更慢。因此保持缓存默认关闭，按实际负载启用。
- 含预热，501 次读取对应的 SQLite 好友查询从 501 次降为 1 次；命中部分不再查 SQLite。
- 这是特定数据集的查询微基准，不能推导聊天 QPS 或端到端 P99。

## 可加入简历的亮点
针对好友列表刷新与好友群发中的重复关系查询，引入 Redis Cache-Aside 缓存，设计 TTL、空结果缓存及好友增删后的双向失效；通过实例命名空间与故障后版本切换避免恢复时读取旧缓存，实现 Redis 超时自动回源 SQLite。在 5 万条好友关系的重复查询测试中，501 次读取仅触发 1 次 SQLite 查询，并通过缓存故障与恢复一致性测试。

## 当前边界
Redis 使用同步 hiredis，由数据库锁保护，网络等待仍会占用 I/O 线程；未实现异步 Redis、连接池、多实例即时失效或分布式在线会话。实际收益随好友数量、缓存命中率和网络时延变化。
